# ADR-003: Управление секретами: Переменные окружения
Дата: 2025-09-22
Статус: Accepted

## Context
Для устранения риска **R-06** (Несанкционированный прямой доступ к БД) и обеспечения безопасности критических данных (пароль БД, ключи API) необходимо исключить их из репозитория и логов. Текущий DFD показывает прямую связь P3 (Бэкенд) с D4 (База данных), требующую строгой аутентификации.

## Decision
Все конфигурационные параметры, представляющие собой секреты (credentials, ключи шифрования), должны загружаться исключительно из **переменных окружения** при запуске Бэкенда.
1.  **Источник:** Переменные окружения (Environment Variables).
2.  **Запрет:** Абсолютный запрет на хранение секретов в файлах конфигурации, которые попадают в Git, или жесткое кодирование в `src/`.
3.  **Инициализация:** Сервис должен падать (`fail-fast`), если необходимая переменная окружения (например, `DB_PASSWORD`) отсутствует.

**Параметры:**
* Пример переменной: `DB_PASSWORD`.

## Consequences
**Плюсы:**
* **Снижение R-06 (Уровень риска: 4):** Устранение риска компрометации через утечку исходного кода/репозитория.
* **Упрощение ротации:** Секреты легко обновляются без пересборки/перезапуска сервиса (только обновление ENV/Secret Manager).
* Соответствие принципу 12 Factor App.

**Минусы:**
* Необходимость использования более сложного механизма управления секретами (Vault, Kubernetes Secrets) на Production, что требует дополнительной настройки инфраструктуры (DevOps).

## Alternatives
- Использование файлов .env
- Использование Секрет-Менеджеров даже для среды разработки
