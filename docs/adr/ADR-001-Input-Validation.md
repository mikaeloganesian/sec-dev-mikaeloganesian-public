# ADR-001: Защита загрузки файлов и валидация ввода
Дата: 2025-09-22
Статус: Accepted

## Context
В целях снижения рисков, связанных с приемом внешних данных, включая **R-07** (Отсутствие валидации входных данных) и потенциальные атаки через загрузку (Path Traversal, исполнение вредоносных файлов), необходимо внедрить строгую валидацию на уровне Бэкенда (P3). Текущее решение касается будущего функционала загрузки контента, но принципы применимы ко всему вводу (поток F2).

## Decision
Внедрить централизованный модуль безопасной загрузки/валидации, основанный на строгих политиках:
1.  **Проверка содержимого:** Использовать сигнатуры файлов (`\x89PNG`, `\xff\xd8` JPEG) для подтверждения типа, независимо от расширения.
2.  **Лимиты:** Ограничение размера файла (порог: `MAX_BYTES = 5MB`).
3.  **Имя файла:** Всегда использовать **UUID** для имени, чтобы избежать конфликтов и раскрытия структуры.
4.  **Канонизация путей:** Использовать `pathlib.Path.resolve()` и строгую проверку `path.startswith(root)` для предотвращения Path Traversal.

**Конфигурация:**
* `MAX_BYTES = 5_000_000`
* Разрешенные типы: `image/png`, `image/jpeg`.

## Consequences
**Плюсы:**
* **Снижение R-07 (Уровень риска: 6):** Предотвращение загрузки вредоносного или слишком большого контента.
* **Повышение безопасности:** Исключение возможности Path Traversal и XSS через имя файла.
* **DX:** Четкий, переиспользуемый модуль для обработки загрузок.

**Минусы:**
* Накладные расходы на чтение всего файла в память для проверки `Magic Bytes`.
* Усложнение логики сохранения (замена имени на UUID).

## Alternatives
- Ручная валидация в обработчиках FastAPI
- Использование обособленной библиотеки валидации
